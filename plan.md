## Phase-2 verification contract

Run exactly `cd taskboard && python -m pytest -q tests`. This phase must preserve all phase-1 API behavior while adding the browser-facing task/project UI. The tests must prove that the template contains the project form, project list, filter, loading, empty, and error regions, and that it loads `/static/app.js` and `/static/style.css`. JavaScript must use `textContent` for user-controlled values, update DOM collections with `replaceChildren`, and call the specified `/api/projects` routes rather than embedding server data or unsafe HTML.

The fixture in `taskboard/tests/conftest.py` must isolate every API test with a temporary `TASKBOARD_DB_PATH`, reload `taskboard.main`, construct the application through `create_app`, and yield a FastAPI `TestClient`. Repository tests must exercise the SQLite-backed project/task persistence contracts already defined by SPEC and architecture, including creation, retrieval, update, deletion, ordering/filter behavior, and the empty-result cases required by the existing API. API tests must assert the exact HTTP methods, paths, JSON fields, status codes, and validation behavior in SPEC; they must cover project listing/creation/update/deletion and task operations without depending on data from another test.

The HTML bead owns semantic regions and controls only; the JavaScript bead owns fetching project data, rendering loading/error/empty states, filtering, and safe event-driven updates; the stylesheet bead owns the responsive Kanban layout, columns/cards, form, filter, and state visibility without changing API semantics. The UI content test bead provides focused static assertions for these boundaries, while the repository and API test beads remain compatible with the completed phase-1 implementation. Do not add routes, persistence fields, configuration, or UX features not stated in SPEC.

## Acceptance checklist

- All seven phase-2 required paths exist at their exact `taskboard/` locations.
- `pytest` completes with no failures and exercises both the cached UI-content assertions and the phase-1 regression suite.
- No implementation or test uses unsafe HTML interpolation for project/task/user-controlled text.
- Browser assets reference the exact API paths and controls specified by SPEC, and the page remains usable for loading, empty, success, filtered, and error responses.
